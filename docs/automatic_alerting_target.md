# 自动捕捉与告警目标态

## 1. 目标态定义

这个项目的目标态，不是一个主要靠人工阅读和人工判断的研究框架。

它的目标态是：

- 一个部署在服务器上的 `全行业自动扫描系统`
- 一个围绕 `多重共振信号` 运行的 `行业起势捕捉系统`
- 一个在触发阈值后自动向你推送提醒的 `告警系统`

换句话说，这个项目最终要回答的是：

- 在全行业范围内，哪些行业正在出现“即将爆发”的前兆
- 这些前兆是不是来自多个节点的共振，而不是单点噪音
- 一旦出现这种共振，系统能不能自动识别、自动记录、自动推送

## 2. 多重共振的基本定义

这里的 `多重共振` 默认不是单一因子触发，而是至少来自多个维度同时升温。

当前建议的主节点包括：

- `交易 / 资金信号`
  - 行业强度、扩散、成交占比、龙头先行、板块结构变化
- `新闻 / 叙事信号`
  - 新闻量增速、主题聚类、来源扩散、叙事收敛
- `基本面代理信号`
  - 行业经营状态的高频代理变量，如价格、库存、需求、供给、盈利、订单、价差
- `政策 / 预期信号`
  - 政策催化、制度变化、盈利预期修正

默认思想是：

- 单点信号只能记为线索
- 多节点共振才进入强提醒

## 3. 自动系统的最小闭环

目标态最小闭环建议是：

1. 服务器定时扫描全行业
2. 对新闻、交易、基本面等信号做行业级聚合
3. 计算多节点共振状态
4. 对达到阈值的行业生成结构化告警事件
5. 通过消息渠道自动推送
6. 把告警结果和快照写入日志与状态层，供后续复盘

## 4. 目标输出

目标态系统至少要输出两类东西：

### 实时 / 准实时输出

- 新触发行业
- 触发时间
- 共振强度
- 主要触发节点
- 代表标的
- 简短原因摘要

### 可复盘输出

- 每次告警的结构化事件记录
- 触发前后的行业状态变化
- 后验表现
- 假阳性 / 漏报分析

## 5. 推送层要求

这个项目的推送层不应是“顺手补一个通知”。

推送层本身就是目标态的一部分。

默认要求包括：

- 只在 `未触发 -> 已触发` 时推送新告警，避免重复轰炸
- 告警消息里保留最少但关键的信息
- 支持未来扩展多个通道，例如：
  - Bark
  - webhook
  - 邮件
  - 其他消息服务

当前项目里已有可参考的推送基础设施思路，但那只是 `推送机制参考`，不是本项目的信号逻辑来源。

## 6. 与既有行业研究的关系

既有行业研究不能被当作：

- 项目对象模板
- 样板对象定义来源
- 策略逻辑蓝本

它们最多只能提供：

- 某些行业的基本面变量灵感
- 某些产业链拆解角度
- 某些容易失真的经验提醒

也就是说：

- `研究结论` 不照搬
- `对象边界` 不照搬
- `信号逻辑` 不照搬
- 最多借一点 `基本面思路`

## 7. 当前阶段与目标态的关系

当前项目还没有进入服务器部署和自动推送阶段。

但从项目规划上，目标态已经明确是：

- `全行业自动扫描`
- `多重共振识别`
- `自动推送告警`

这意味着后续节点设计都应该反过来服务这个目标，而不是停留在“写研究笔记”层面。

## 8. 下一步

为了向这个目标态推进，当前最自然的下一步是：

1. 固定全行业覆盖骨架
2. 定义“多重共振”的起势标签口径
3. 设计行业级自动扫描的最小输入集合
4. 设计告警事件结构和推送规则
