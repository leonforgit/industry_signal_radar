# 可行性与资源规划

## 1. 这份文档回答什么

这份文档回答的是：

- 以我们当前的配置和能力，能不能把这个项目做成
- 能做到什么程度，才算 `可用系统`
- 还缺哪些资源
- 信息源、新闻源、数据源应该怎么分层接入

它不回答：

- 每个行业的具体指标细节
- 每条规则的最终阈值
- 最终模型该用什么算法

这些问题后续由节点文档继续细化。

## 2. 直接结论

### 结论 1：能做成 `可用的 v1`

基于当前条件，我的判断是：

- 我们 `能做成一个可用的行业起势自动捕捉系统 v1`
- 这个 v1 可以做到：
  - 覆盖全行业骨架
  - 日频或半日频扫描
  - 自动拉取多源信号
  - 识别一部分多重共振候选
  - 自动推送可解释告警

### 结论 2：当前还做不成“机构级全量实时情报系统”

以当前条件，不适合直接承诺：

- 全量实时新闻流处理
- 全行业统一高质量高频基本面代理覆盖
- 大规模毫秒级或分钟级事件流告警
- 完全依赖公开免费源的稳定生产级系统

如果要走到这一步，后续需要更强的数据源、存储和运维投入。

### 结论 3：当前最大的缺口不是算力，而是 `信号采集与压缩层`

我们现在最缺的不是：

- 服务器有没有
- 定时能不能跑
- 推送能不能发

我们最缺的是：

- 全行业对象映射
- 多源采集入口
- 新闻去重与聚类
- 行业标签映射
- 多节点共振规则
- 告警去重与复盘日志

## 3. 当前已有能力

结合现有量化子工作区基础设施，当前已经具备这些可复用能力：

### A. 远端运行底座

- private remote runtime 远端节点已经在稳定承接日更任务
- 已有 `systemd timer + wrapper + log + config` 结构
- 已有状态产物、指标导出和恢复手册

这意味着：

- 新系统不需要从零搭运维骨架
- 可以复用现有远端运行纪律

### B. Python 数据抓取与处理基础

- 当前工作区已经在使用 `AKShare + yfinance`
- Python 侧抓取和解析能力已经够做第一版采集器
- 仓库对 `共享状态 / 输出产物 / 文档回写` 已经有清晰纪律

### C. 项目文档和主控机制

- 已有 `master_plan`
- 已有 `success_criteria`
- 已有 `automatic_alerting_target`
- 已有外部对标扫描

这意味着：

- 现在进入资源和节点规划是顺势推进，不是另起炉灶

## 4. 当前缺口

要把项目从“方向成立”推进到“系统可用”，还缺这 6 类东西：

### 1. 行业对象与别名映射

需要解决：

- 行业、主题、概念、产业链节点如何统一映射
- 同一主题在不同时间如何换名字、换龙头

### 2. 多源采集器

需要稳定接入：

- 公告
- 政策
- 新闻
- 市场交易
- 行业经营代理变量

### 3. 新闻压缩层

必须补上：

- 去重
- 相似报道归并
- 事件聚类
- 行业归属
- 叙事标签

否则新闻越多，噪音越大。

### 4. 信号标准化层

需要把不同频率、不同格式的输入压成统一结构：

- 时间对齐
- 变化率
- 行业相对强弱
- 异常程度

### 5. 共振与告警治理

需要定义：

- 什么叫触发
- 什么叫升级
- 什么叫重复噪音
- 什么情况下 suppress

### 6. 复盘数据库

需要保留：

- 触发时间
- 触发节点
- 原始证据摘要
- 后验结果
- 人工反馈

## 5. 项目可达成的目标分层

### 阶段 1：研究原型

当前就能做。

能力目标：

- 跑全行业骨架
- 能生成行业状态快照
- 能保存候选共振事件

### 阶段 2：可用内部告警系统

当前条件下 `可以做成`，也是最现实的近期目标。

能力目标：

- 用公开源或低成本源覆盖主要行业
- 日频或半日频触发
- 触发后自动推送
- 告警可解释、可复盘

### 阶段 3：高强度生产系统

当前条件下 `暂时不应该直接承诺`。

额外需要：

- 更多付费数据源
- 更稳定的采集授权
- 更强的存储、任务队列、监控和回放能力

## 6. 资源需求总表

当前把资源需求拆成 4 层：

1. `工程资源`
2. `信息源`
3. `新闻源`
4. `数据源`

## 7. 工程资源需求

### 当前已具备

- 远端定时运行能力
- 远端日志与输出管理
- Python 数据处理环境
- 文档化主控流程

### 仍需补齐

- 项目独立运行配置
- 事件数据库
- 采集缓存目录
- 告警去重状态表
- 失败重试与健康检查
- 推送渠道正式接入

### v1 推荐工程形态

- 任务调度：`systemd timer` 或等价定时调度
- 事件存储：`SQLite` 起步
- 原始缓存：repo 外部目录
- 配置管理：项目内 `config/schema/manifest`
- 推送通道：`Bark + webhook` 优先

## 8. 信息源规划

这里的 `信息源` 指的是：

- 政策文件
- 公告
- 官方发布
- 行业协会信息
- 监管口径

它们不等同于媒体新闻，也不等同于行情数据。

### A. v1 必接信息源

#### 1. 交易所与公告

- [巨潮资讯](https://www.cninfo.com.cn/)
- [上交所](https://www.sse.com.cn/)
- [深交所](https://www.szse.cn/)
- [北交所](https://www.bse.cn/)

用途：

- 上市公司公告
- 问询函 / 监管措施
- 调研、融资融券、股东变化等硬信息

#### 2. 政策与部委发布

- [中国政府网政策文件库](https://www.gov.cn/zhengce/zhengcewenjianku/)
- [工业和信息化部运行监测协调局信息发布](https://www.miit.gov.cn/jgsj/yxj/xxfb/index.html)
- [国家统计局国家数据](https://data.stats.gov.cn/)

用途：

- 产业政策
- 稳增长、扩产、供给侧、产业规范等文件
- 行业运行情况与宏观分行业数据

#### 3. 行业主管部门与专项官方口径

按行业逐步扩展，例如：

- [农业农村部](https://www.moa.gov.cn/)
- [国家能源局](https://www.nea.gov.cn/)
- [国家发展改革委](https://www.ndrc.gov.cn/)
- [商务部](https://www.mofcom.gov.cn/)

用途：

- 行业专项政策
- 月度/季度运行情况
- 供需、产量、价格、进出口相关口径

### B. v2 应接信息源

- 行业协会官网
- 重点企业官网新闻中心 / 提价函 / 经营快讯
- 地方政府与地方产业主管部门发布

### C. 当前提醒

- 信息源是可解释性的核心来源
- 这层比论坛和社媒更适合做高权重触发

## 9. 新闻源规划

这里的 `新闻源` 指：

- 财经媒体
- 快讯流
- 深度报道
- 论坛 / 社区舆情

### A. v1 必接新闻源

我建议 v1 先用 `硬新闻 + 主流财经媒体`，不要一开始就扑向全网社媒。

优先层：

- [财联社](https://www.cls.cn/)
- [证券时报](https://www.stcn.com/)
- [中证网 / 中国证券报](https://www.cs.com.cn/)
- [中国证券网 / 上海证券报网络版](https://www.cnstock.com/)
- [界面新闻](https://www.jiemian.com/)
- [澎湃新闻财经](https://www.thepaper.cn/)

用途：

- 事件快讯
- 板块异动报道
- 产业政策与景气新闻
- 行业龙头公司新闻

### B. v1 低权重辅助新闻源

- [雪球](https://xueqiu.com/)
- 东方财富股吧 / 主题页
- 其他股票论坛

用途：

- 观察叙事扩散
- 观察散户端关注度

注意：

- 这层只能做低权重辅助
- 不能直接作为高置信告警依据

### C. 新闻层最关键的工程要求

不是“抓得越多越好”，而是必须先做：

- 标题去重
- 转载归并
- 事件聚类
- 行业映射
- 来源分层

## 10. 数据源规划

这里的 `数据源` 指：

- 市场价格和成交数据
- 资金流与交易结构数据
- 行业经营状态代理变量
- 宏观与专项统计数据

### A. v1 必接数据源

#### 1. 市场 / 交易结构

- [AKShare 文档](https://akshare.akfamily.xyz/)
- [yfinance](https://pypi.org/project/yfinance/)
- [JoinQuant 行业概念数据](https://www.joinquant.com/help/api/plateData)
- [Tushare Pro 文档](https://tushare.pro/document/2)

主要用途：

- 行业指数 / 板块 / 概念行情
- ETF 与代表股价格、成交额、波动率
- 北向、融资融券、成交额等交易结构变量
- 行业成分和概念映射

当前建议：

- `AKShare + yfinance` 继续作为 v1 主数据底座
- `JoinQuant / Tushare` 作为补充映射与补缺工具，不急着一开始强依赖

#### 2. 官方统计与行业经营代理

- [国家统计局国家数据](https://data.stats.gov.cn/)
- [工业和信息化部运行监测协调局信息发布](https://www.miit.gov.cn/jgsj/yxj/xxfb/index.html)
- [农业农村部](https://www.moa.gov.cn/)
- [国家能源局](https://www.nea.gov.cn/)

主要用途：

- 行业产量、产销、营收、增加值
- 农产品、能源、制造业运行指标
- 官方分行业景气与运行数据

### B. v2 可能需要的行业专属数据源

这类源往往决定行业深度，但不必在 v1 全面铺开。

例如：

- 钢铁 / 煤化工 / 黑色链：价格、库存、开工率类行业数据
- 光伏链：硅料、硅片、电池片、组件价格与排产
- 生猪链：猪价、仔猪价、母猪存栏、饲料成本、出栏节奏
- 航运：运价、吞吐量、运力供给

这一步通常会出现两类情况：

1. 官方源能覆盖一部分
2. 真正高频、好用的数据需要行业专业源或付费源

### C. 后续高概率要考虑的付费源

如果后面要做更深、更稳的行业代理层，大概率会逐步接触：

- Wind / Choice
- 同花顺 iFinD
- Mysteel
- SMM
- InfoLink
- 生意社
- 更稳定的财经快讯 / 媒体 API

当前判断：

- 这些不是 v1 必需
- 但其中一部分很可能会成为重点行业深挖阶段的升级件

## 11. v1 最小可行接入清单

如果目标是“先做出一个真正可用的系统”，我建议先把源控制在下面这个规模：

### 信息源

- 巨潮资讯
- 中国政府网政策文件库
- 工信部运行监测协调局
- 国家统计局国家数据
- 2 到 4 个行业主管部门官网

### 新闻源

- 财联社
- 证券时报
- 中证网
- 中国证券网
- 1 到 2 个综合财经媒体
- 雪球仅作低权重辅助

### 数据源

- AKShare
- yfinance
- JoinQuant 或 Tushare 二选一补充
- 官方统计与部委运行数据

## 12. 当前最现实的项目判断

### 能不能做成

能。

### 能不能做出可用系统

能，但这里的“可用”应该定义为：

- 能稳定扫描
- 能输出行业状态候选
- 能抓到一部分值得你立刻打开研究的行业
- 能自动推送
- 能留下可复盘记录

### 现在最不该做的事

- 一开始就追求全量实时
- 一开始就接过多低质量新闻源
- 一开始就把论坛热度当主信号
- 一开始就为全行业全部基本面变量付费

## 13. 当前推荐下一步

当前最自然的下一步是：

1. 把 `v1 接入清单` 定稿
2. 把 `信息源 / 新闻源 / 数据源` 写成 manifest
3. 先搭 3 个稳定入口：
   - `collect_information_signals.py`
   - `collect_news_signals.py`
   - `collect_market_structure_signals.py`
4. 再定义第一版共振触发规则和告警载荷

## 14. 一句话判断

如果把这轮判断压成一句话，我的结论是：

`以我们当前的底座，完全有机会做出一个可用的全行业多重共振预警系统 v1；当前最大的瓶颈不是服务器，而是如何把公开信息源、新闻源和数据源压缩成高信噪比的行业级事件流。`
