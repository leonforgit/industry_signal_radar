# Radar 参考标准 V1

这份文档把外部案例压缩成 Radar 日报与系统建设的产品标准。它不追求复刻某个机构的具体页面，而是回答：一个真正可用的雷达系统，应该如何从信息流变成 PM 的早晨决策界面。

## 1. 对标案例

### GDELT：全球新闻事件底座

[GDELT](https://www.gdeltproject.org/) 的核心启发不是“新闻多”，而是把全球新闻媒体转成可计算的事件、实体、地点、情绪和主题图谱。它公开说明其新闻监测覆盖 100 多种语言、跨国家来源，并以接近实时的方式更新。

对 Radar 的启发：

- 输入层必须先结构化，不应直接把新闻标题堆给 PM。
- 事件要有实体、主题、来源、时间、地理/市场范围和情绪语义。
- 每个事件都要能追踪历史脉络，而不是只看当天标题。

### HealthMap：公共卫生事件预警系统

[HealthMap](https://www.healthmap.org/about/) 把新闻聚合、目击报告、专家讨论和官方报告合成同一个疫情监测视图，并通过自动流程持续监控、过滤、可视化和分发。

对 Radar 的启发：

- 多源输入要分可靠性层级：官方公告、结构化新闻、专家/机构观点、市场代理变量不能混成同一种证据。
- “早发现”必须配套去重、过滤和复核，否则会变成噪音放大器。
- 输出要面向行动者，重点是地点/对象、当前状态、变化速度和下一步处置。

### IMF PortWatch：港口与供应链冲击监控

[IMF PortWatch](https://www.imf.org/en/news/articles/2023/11/13/pr23390-imf-university-oxford-launch-portwatch-platform-monitor-simulate-trade-disruptions) 的启发是把 AIS/港口数据转成贸易中断的实时监控与模拟工具，用于决策者判断冲击及外溢影响。

对 Radar 的启发：

- 对行业机会，不能只写“行业热度上升”，必须挂上代理变量和可交易/可观察标的。
- 对供应链、能源、航运这类主题，要有 chokepoint、运价、供给、库存、贸易流等持续变量。
- 好的雷达不只识别事件，还要模拟事件的扩散路径和验证节点。

### Event-driven Fund：PM 视角

[BlackRock Event Driven Equity Fund](https://www.blackrock.com/us/partner/literature/fact-sheet/bilpx-event-driven-equity-fund-factsheet-us09250j7349-us-en-individual.pdf) 把事件驱动定义为围绕并购、分拆、重组、管理层变化等重大公司事件寻找机会，并强调结果取决于催化事件是否发生或完成。[Taconic](https://taconiccap.com/investment-approach/event-driven/) 也把 event-driven 拆为 merger arbitrage 与 catalyst-driven equities，后者强调有明确催化、事件或公司变化的 idiosyncratic situations。

对 Radar 的启发：

- PM 早晨需要看的不是新闻摘要，而是 catalyst book：发生了什么、是否已定价、剩余路径、失败方式、今天该做什么。
- 财报类事件如果已经被价格和量能反映，只能作为承接验证，不应占据高权重机会位。
- 代表股、ETF、同行扩散和反证变量，是行业机会能否进入研究流程的必要字段。

## 2. Radar 日报目标形态

一份合格日报应控制在一到两页，默认结构为：

- 今日关键事件：宏观、行业、公司、风险事件混排；每条必须写清事件、影响方向、逻辑传导、可观察标的、情景弹性和今日动作。
- 三条作战线：只展开最值得今天打开的 2-3 条机会。
- 中长期隐性线索：写清征兆、方向、验证、反证，避免只写“继续关注”。
- IPO / 打新申购窗口：A/H 新股都覆盖，优先使用中文名；核心问题是“是否值得申购 IPO 股份”，而不是上市后二级买入或首日承接跟踪；可申购与不达标对象都要用表格化研究卡片展示结论。
- 后台状态：只保留影响发布可信度的门禁，不展示工程噪音。

## 3. 质量门禁

日报生成前必须完成以下预检：

- 价格预检：公司事件要拿到目标交易日价格；业绩类事件若已明显上涨/放量，自动降权。
- 首日确认：事件发生在最新价格样本之后，只能等待系统自动补齐首个交易日承接验证，不得机械降权。
- 行业标的：行业机会必须带代表股和 ETF，不得写成泛主题。
- Kimi 前置研究：Kimi 不能把“核实真实性”留给 PM，而要先根据已有 context 做初筛、降权和动作建议。
- IPO 申购预检：港股日历若给英文名，系统层要尽可能映射中文名称；报告必须展示招股书业务/财务/风险、申购拥挤度、可比公司估值、保荐人/基石信息；已过窗口或不达标对象进入“不达标 / 跳过”组并保留复盘原因。

## 4. 后续能力缺口

下一阶段不应只继续加新闻源，而应补这些能力：

- catalyst taxonomy 的可回测标签化。
- milestone engine：每条事件线索的下一时间点、监管节点、公告节点、首个交易日确认节点。
- proxy library：行业专属代理变量与 ETF/代表股跟踪。
- false-positive book：把被价格兑现、无扩散、无二级证据的失败样本沉淀下来。
- research handoff：把 Kimi 初筛后的动作直接交给后续研究脚本或人工研究队列。
