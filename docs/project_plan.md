# 项目总计划

> 说明：`docs/master_plan.md` 是当前项目的唯一主控规划文档；本文件用于补充阶段拆解和推进顺序，不替代主控入口。

## 1. 项目目标

构建一个多源信号驱动的 `行业起势预警系统`，用于识别行业从冷到热的早期升温过程，并输出：

- 行业状态
- 升温概率
- 证据链
- 近期变化原因

## 2. 非目标

当前阶段不把以下内容作为默认目标：

- 自动交易执行
- 一开始就把所有节点都做到全行业生产级
- 完全实时的新闻情报平台
- 单一模型直接预测所有行业拐点

## 3. 项目阶段

### 阶段 A：框架设计

目标：

- 定义项目边界
- 定义行业起势标签
- 定义一级节点与模块关系

交付物：

- `README.md`
- `STATUS.md`
- `reports/main.md`
- 系统架构文档
- 节点地图

### 阶段 B：全行业对象骨架与原型样板集

目标：

- 确定全行业覆盖骨架
- 确定原型样板集
- 确定行业分类口径
- 确定行业映射标的、ETF、龙头和产业链节点

交付物：

- 全行业对象骨架规则
- 原型样板清单
- 行业对象映射表
- 主题变体与别名表

### 阶段 C：节点化设计

目标：

- 逐个细化资金、基本面、新闻、政策预期、技术 / tape 节点
- 明确每个节点的输入、输出、频率、来源和风险

交付物：

- 节点计划文档
- 节点数据源清单
- 节点最小可行信号定义

### 阶段 D：历史验证

目标：

- 回看历史启动案例
- 纳入失败和假启动样本
- 判断单节点与组合节点的区分度

交付物：

- 历史案例集
- 标签定义文档
- 验证结果摘要

### 阶段 E：研究版原型

目标：

- 生成行业状态样例
- 生成证据链卡片
- 生成阶段性行业雷达摘要

交付物：

- 研究版状态面板
- 周度 / 日度摘要模板
- 初版评分与状态机规则

### 阶段 F：可持续运行版

目标：

- 只对证明有价值的节点做工程化
- 建立增量更新、缓存、去重和监控

交付物：

- 稳定脚本入口
- 运行清单
- 轻量验证脚本

## 4. 默认推进顺序

当前默认顺序是：

1. 行业对象层
2. 起势定义与标签层
3. 基本面层
4. 新闻层
5. 资金层
6. 评分与状态机层
7. 历史验证层

这样做的原因是：

- 行业对象和标签不清，后面的信号抓再多也很容易散
- 基本面层决定了行业专属知识图谱的质量
- 新闻层最容易长出大量工程负担，因此需要放在清晰边界之后

## 5. 当前里程碑

当前里程碑不是“抓到第一批新闻”，而是：

- 建立稳定的项目骨架
- 建立系统级计划
- 确定第一批细化节点

## 6. 完成标准

项目进入下一阶段前，至少应满足：

- 研究对象有清晰边界
- 节点定义不互相打架
- 数据工程负担与项目价值大致匹配
- 主报告和状态文档能独立解释项目当前在做什么
