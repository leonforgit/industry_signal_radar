# 行业对象层第一轮细化

## 1. 这一层要解决什么问题

行业起势预警系统如果没有清晰的研究对象，后面的新闻、基本面、资金和状态机都会发散。

这一层的任务不是直接给出信号，而是先回答：

- 我们到底在跟踪什么对象
- 行业、主题、产业链、板块之间如何区分
- 一个对象在市场上应该由哪些代理标的来观察
- 如何在 `全行业覆盖` 和 `重点深挖` 之间建立分层结构

## 2. 第一轮细化的核心结论

### 结论 1：覆盖目标应面向全行业，但对象定义不能等同于单一官方分类

这个项目的最终覆盖目标应面向 `全行业`。

但这不意味着项目对象可以简单等同于“申万一级行业”或“中信一级行业”。

更合适的做法是把对象拆成 4 层：

1. `覆盖骨架层`
   - 用稳定、可维护的官方分类来保证全行业都被纳入
   - 第一版建议优先以 `申万一级` 作为覆盖骨架，并保留向 `申万二级` 的映射扩展位
2. `研究对象层`
   - 我们真正要跟踪的行业、赛道或产业链对象
   - 例如：`生猪养殖`、`光伏主链`、`中国券商`、`中国 AI 数据中心 / 算力链`
3. `主题 / 产业链覆盖层`
   - 用来承接跨行业主题、产业链对象和市场叙事对象
   - 避免只靠官方行业分类丢失真正重要的赛道结构
4. `交易代理层`
   - 指数、ETF、龙头股、代表股和产业链关键公司
   - 用来观察价格、资金、扩散和技术结构

这几层分开之后，项目才能同时适应：

- 全行业纳入
- 稳定的研究对象
- 会变化的市场叙事
- 可交易的市场代理

### 结论 2：原来的几个行业只能作为“原型样板集”，不能被误解为项目边界

原型样板集的作用是：

- 前期校准节点框架
- 发现不同起势机制的差异
- 为后续全行业覆盖提供模板和失败经验

它们不是：

- 项目的最终覆盖边界
- 唯一值得跟踪的对象
- 未来状态系统的全部输出对象

原型样板集的选择标准是：

- 能覆盖不同类型的起势机制
- 有相对清晰的基本面代理变量
- 有可观察的市场代理标的
- 有重复出现的历史阶段
- 能帮助校准自动捕捉系统的不同失真场景

### 结论 3：行业对象底表必须分成“全行业覆盖骨架”和“原型样板集”两部分

后续所有节点都应该围绕同一张对象表工作。

这张底表至少要分两层回答：

1. `覆盖骨架`
   - 全行业有哪些稳定对象被纳入
   - 它们的官方分类、映射和基础代理是什么
2. `原型样板集`
   - 哪些对象先被拿来做方法开发和深度校准

具体字段上，至少要回答：

- 对象是谁
- 对象属于哪一类
- 它的主要起势机制是什么
- 它有哪些官方分类和主题别名
- 它对应哪些市场代理和龙头
- 它当前是否进入重点跟踪池

## 3. 行业对象的建议结构

当前建议每个对象至少维护这些字段：

- `object_id`
  - 稳定 ASCII 标识
- `display_name_cn`
  - 中文显示名
- `display_name_en`
  - 英文显示名
- `object_kind`
  - `industry` / `theme` / `industry_chain` / `financial_subsector`
- `signal_archetype`
  - 主要起势机制
- `market_scope`
  - A 股 / 港股 / 美股 / 跨市场
- `official_classifications`
  - 申万 / 中信 / GICS 等辅助标签
- `theme_aliases`
  - 市场常见别名、叙事别名
- `representative_index_or_etf`
  - 代表性指数或 ETF
- `leader_tickers`
  - 龙头或核心映射标的
- `leading_signal_families`
  - 优先观察的信号族
- `legacy_research_usage`
  - 如有既有行业研究，最多只记录可借鉴的基本面思路，不把其当作对象模板
- `priority_tier`
  - `P0 / P1 / P2`
- `status`
  - `candidate / active / deferred`

## 4. 原型样板集选择规则

原型样板集默认按以下规则挑选：

- `机制差异化`
  - 不能全部是同一种行情机制
- `代理变量可得`
  - 基本面或市场代理至少要有可持续观测的抓手
- `市场代理清晰`
  - 要有指数、ETF 或一组核心代表股
- `历史上有重复阶段`
  - 方便后续历史验证
- `能独立于既有研究存在`
  - 不把过去的行业研究主稿当成对象定义来源

## 5. 全行业覆盖骨架建议

### 第一版覆盖骨架

第一版建议采用：

- `申万一级行业` 作为全行业覆盖骨架

原因是：

- 稳定
- 常用
- 足够宽，便于先把全行业纳入
- 后续仍可向二级行业和主题对象扩展

### 第一版覆盖逻辑

第一版建议按以下顺序组织：

1. 全行业先纳入 `申万一级`
2. 对研究价值特别高、内部结构差异特别大的板块，再保留向 `申万二级` 的扩展位
3. 对明显跨行业但研究上重要的赛道，再叠加 `主题 / 产业链对象`

这意味着：

- 覆盖层面上我们追求的是“全行业都在雷达里”
- 深度层面上我们允许不同对象有不同细化进度

## 6. 原型样板集建议

### P0 样板

#### 1. 生猪养殖

- 对象类型：`industry`
- 起势原型：`价格 + 库存/产能 + 周期反转`
- 适合原因：
  - 起势机制相对清晰
  - 高关注度价格变量和盈利变量都比较直观
  - 非常适合检验“基本面先动，市场后反应”的场景

#### 2. 光伏主链

- 对象类型：`industry_chain`
- 起势原型：`价格 + 产能 + 库存 + 政策/装机`
- 适合原因：
  - 产业链长，信息密度高
  - 新闻层、基本面层和市场层都容易长出信号
  - 很适合测试“链条式传导”而不是单点行业

#### 3. 中国券商

- 对象类型：`financial_subsector`
- 起势原型：`流动性 + 风险偏好 + 政策 + 成交放大`
- 适合原因：
  - 不是商品周期逻辑，能补足另一类机制
  - 资金层和技术 / tape 层往往很关键
  - 适合检验“市场先动、基本面后跟”的结构

#### 4. 中国 AI 数据中心 / 算力链

- 对象类型：`theme` + `industry_chain`
- 起势原型：`主题扩散 + capex + 订单预期 + 政策叙事`
- 适合原因：
  - 适合测试“主题叙事”和“产业链验证”并存的对象
  - 能检验新闻层与基本面层的边界

### P1 样板

#### 5. 中国煤化工

- 对象类型：`industry_chain`
- 起势原型：`价差 + 成本 + 周期修复`
- 适合原因：
  - 更适合验证“利润分配 / 价差修复”型起势
  - 能测试行业链内部结构变化是否先于板块普涨

## 6.1 与既有行业研究的关系

既有行业研究在这个项目里最多只能提供：

- 某些基本面变量的假设灵感
- 某些产业链拆分角度
- 某些失真风险提醒

它们不能被当作：

- 对象边界定义
- 原型样板集来源
- 自动信号逻辑蓝本

## 7. 当前不建议第一轮就作为原型样板集纳入的对象

以下对象不是不能做，而是不建议在第一轮就放进原型样板集：

- 纯事件驱动、生命周期很短的题材
- 缺少清晰基本面代理变量、只能靠热度描述的主题
- 没有稳定市场代理、只能靠零散个股拼接的对象
- 过度依赖单一新闻源才可观察的对象

## 8. 第一轮输出

这一轮行业对象层细化，先产出两类东西：

1. 规则
   - 全行业覆盖骨架的定义方式
   - 原型样板集的选择标准
2. 底表框架
   - 原型样板对象清单
   - 全行业覆盖骨架的组织原则

这意味着当前阶段先建立 `全行业对象框架`，但还不急着把所有深层节点都一次性补齐。

当前阶段不急着建立的是：

- 动态主题自动抽取
- 所有行业的完整深层信号图谱

## 9. 当前遗留问题

- 覆盖骨架是否只用申万一级，还是第一版就带申万二级
- 交易代理层是否先用“龙头篮子”而不是指数 / ETF
- `AI 数据中心 / 算力链` 这种对象最后应归入 `theme` 还是 `industry_chain`
- 第一批样板是否需要再加入一个消费 / 出行类对象，补足需求恢复型机制

## 10. 下一步

完成行业对象层第一轮细化后，最自然的下一步是：

1. 把全行业覆盖骨架先固定下来
2. 把原型样板集确认下来
3. 为每个样板补最小字段
4. 进入 `起势定义与标签层`

在这之后，再进入基本面层和新闻层细化，效率会更高。
