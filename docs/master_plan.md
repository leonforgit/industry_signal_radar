# 核心规划文档

## 0. 文档定位

这份文档保留 `industry_signal_radar/` 早期阶段的 `背景规划`。

当前更高优先级的统一规划入口已经切换为：

- `docs/radar_system_plan_v1.md`
- `docs/radar_unified_plan.md`

当前项目的 `唯一执行主控文档` 已切换为：

- `docs/execution_checklist.md`

后续这个项目的推进默认遵循：

- 先看 `docs/execution_checklist.md` 确认当前执行状态、已完成项、增量信息与新问题
- 再参考本文件理解项目背景规划、主线和原则
- 每完成一轮节点推进后，先回写 `docs/execution_checklist.md`

这意味着：

- `docs/execution_checklist.md` 是项目级执行总控入口
- `docs/radar_system_plan_v1.md` 是当前系统规划总纲
- `docs/radar_unified_plan.md` 是当前统一规划入口
- `docs/master_plan.md` 是早期背景规划入口
- `docs/project_plan.md` 是阶段拆解与补充说明
- `docs/success_criteria.md` 是项目是否真正有投资价值的判断标准
- `docs/feasibility_and_resource_plan.md` 是当前“能不能做成、缺什么资源”的判断入口
- `reports/main.md` 是长期结论入口
- `workpapers/` 是过程层，不替代主控规划

## 1. 项目目标

构建一个多源信号驱动的 `行业起势预警系统`，用于识别行业从冷到热的早期升温过程，并输出：

- 行业状态
- 升温概率
- 核心证据链
- 近期变化原因
- 触发后的自动告警事件

## 2. 当前非目标

当前阶段明确不把以下内容当作默认目标：

- 自动交易执行系统
- 一开始就把所有节点都做成全行业生产级工程
- 全量实时新闻情报平台
- 只靠单一模型预测全部行业拐点

## 3. 项目原则

- 目标态是 `部署在服务器上的全行业自动扫描与告警系统`
- 研究和验证只是为自动捕捉系统服务，不是项目终点
- 覆盖目标面向 `全行业`，但方法开发可以先用 `原型样板集` 校准
- 先做 `可解释状态`，再追求复杂模型
- 先证明某个节点有增量价值，再为它投入数据工程
- 不把大体量原始语料、缓存或运行时数据库直接堆进仓库

## 4. 当前总阶段

当前处于 `阶段 A：项目框架设计`。

这一阶段的目标不是跑模型，而是把下面几件事定清楚：

- 行业起势到底如何定义
- 系统拆成哪些节点
- 哪些节点优先推进
- 哪些数据工程值得先做
- 哪些事情当前明确不做

## 5. 项目主线

当前默认按 7 条主线推进：

| 主线 | 当前状态 | 当前目标 | 下一步交付物 |
| --- | --- | --- | --- |
| 行业对象层 | 第一轮细化完成 | 定义全行业覆盖骨架、主题映射、代表标的 | 覆盖骨架规则 + 原型样板集 v0 |
| 起势定义与标签层 | 未开始 | 定义什么叫“起势”与失败样本 | 标签口径文档 |
| 基本面层 | 未开始 | 设计行业经营状态代理变量框架 | 基本面节点计划 |
| 新闻层 | 未开始 | 设计新闻层的边界、源清单和压缩逻辑 | 新闻节点计划 |
| 资金层 | 未开始 | 设计行业资金聚集与扩散信号 | 资金节点计划 |
| 评分与状态机层 | 未开始 | 设计行业状态与迁移机制 | 状态机草图 |
| 历史验证层 | 未开始 | 设计历史案例和验证逻辑 | 验证框架草案 |

## 6. 当前优先顺序

当前默认优先顺序如下：

1. 行业对象层
2. 起势定义与标签层
3. 基本面层
4. 新闻层
5. 资金层
6. 评分与状态机层
7. 历史验证层

当前这样排序的原因是：

- 行业对象不清，后面所有信号都会发散
- 标签不清，验证和状态输出都容易变成事后解释
- 基本面层决定了行业专属知识图谱的深度
- 新闻层最容易长出大规模工程负担，因此要放在边界清晰之后

## 8. 节点推进规则

每个节点在进入实质推进前，都要先回答这 5 个问题：

1. 这个节点到底看什么现象
2. 这个节点的输出是什么结构
3. 这个节点依赖哪些数据
4. 这个节点最容易在哪些情况下失真
5. 做这个节点的最小可行版本是什么

每个节点完成一轮后，都要回写：

- 当前判断
- 关键风险
- 是否值得继续工程化
- 下一个最自然动作

## 9. 文档更新规则

后续默认按这个顺序更新：

1. 先更新 `docs/execution_checklist.md`
2. 再更新对应节点文档
3. 再把 durable 结论回并到 `reports/main.md`
4. 如有必要，再更新 `STATUS.md`

如果将来出现执行状态与本文件冲突，以 `docs/execution_checklist.md` 为准，除非明确改写执行主控文档。

## 10. 当前下一步

当前最自然的下一步不是直接搭新闻抓取，而是：

- 先建立全行业覆盖骨架
- 先确认原型样板集
- 先定义统一的“起势”标签口径
- 先把 v1 接入源清单压实

这三件事完成之后，再去细化新闻、基本面和资金节点，项目效率会更高。
