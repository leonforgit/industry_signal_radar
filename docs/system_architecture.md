# 系统架构草图

## 1. 总体定位

这个项目要做的是 `行业起势自动捕捉与告警系统`，不是单一回测策略。

因此架构上要优先服务：

- 全行业自动扫描
- 多源信号接入
- 多重共振识别
- 可解释的状态输出
- 告警推送
- 历史复盘与持续迭代

## 2. 一级模块

当前建议拆成 7 层：

1. 行业对象层
2. 信号采集层
3. 信号标准化层
4. 共振识别与状态机层
5. 告警编排与推送层
6. 验证与回看层
7. 输出与复盘层

## 3. 各层职责

### 行业对象层

负责回答：

- 我们到底在跟踪哪些行业
- 每个行业的核心标的和产业链节点是什么
- 同一主题在不同阶段的别名和代表股如何变化

### 信号采集层

负责拉取多源信息：

- 资金行为
- 行业经营状态代理变量
- 新闻与舆情
- 政策与预期
- 技术 / tape

### 信号标准化层

负责把异质输入变成可比较的结构：

- 时间戳对齐
- 去重和归并
- 缺失处理
- 行业标签映射
- 强弱变化标准化

### 共振识别与状态机层

负责把节点输出压缩成行业状态：

- 单节点分数
- 跨节点合成
- 状态迁移
- 证据链摘要

### 告警编排与推送层

负责回答：

- 什么情况下要发新告警
- 怎样避免重复推送
- 告警应该带哪些最关键的信息

默认输出：

- 结构化告警事件
- 推送载荷
- 告警日志

### 验证与回看层

负责回答：

- 哪些节点真的有增量价值
- 哪些行业更适合被高频代理变量捕捉
- 假启动最常出现在哪些结构里

### 输出与复盘层

负责生成：

- 行业雷达摘要
- 重点行业证据链卡片
- 周度 / 月度复盘
- 历史命中与误判记录

## 4. 仓库内外边界

这个项目未来很容易产生大量数据，因此默认边界要先写清楚。

仓库内适合保存：

- 项目计划和架构文档
- 小型映射表、配置、模式定义
- 小样本 fixture
- 研究结论
- 外部经验扫描笔记

仓库内不适合长期堆放：

- 全量新闻原文库
- 大体量 HTML 抓取缓存
- 运行时数据库快照
- 浏览器会话痕迹
- 高频任务的中间缓存

如果未来出现高体量采集层，默认做法应是：

- 把高体量缓存放到 repo 外部
- 在 repo 内只保留 schema、manifest、样例和总结

## 5. 当前推荐输出口径

当前阶段默认输出 3 类内容：

- `reports/`
  - 主报告和长期判断
- `workpapers/`
  - 过程性扫描、backlog、实验记录
- `output/`
  - 未来的导出摘要、面板快照或发送版产物

## 6. 当前工程原则

- 目标态是自动扫描和自动告警，不是停留在研究笔记层
- 全行业先纳入覆盖骨架，再逐步补深层节点
- 原型样板集只用于方法开发和校准
- 先压缩信息，再扩大抓取规模
- 先保证可解释，再追求模型复杂度
